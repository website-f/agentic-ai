# Local Arisha IT extraction candidate

Not deployed; no live model call, tenant settings, secrets or database writes. Incremental integration base: Connections as merged in main da66952b97dab18aa220b842d1db9ab0b34d255f. This additive candidate depends on the separately reviewed Connections `verifiedEntraAssertion` accessor. Connections patch has been applied explicitly in this isolated integration candidate. ItExtractionController is registered additively in AppModule; CEO-only AI data preview navigation, HTTP/demo client methods, consent/source input, editable proposal fields and source evidence are wired. These changes are packaged separately relative to Connections and do not overwrite its working tree. No operational approval/import action is exposed.

New source: arisha-it-extraction.ts, arisha-it-extraction-azure.ts, arisha-it-extraction.controller.ts. The controller defines GET /api/arisha/it-extraction and POST /api/arisha/it-extraction/preview; these require real linked Entra authentication. Only exact u-fauzan + ceo and current matching Entra OID may request paid inference. Development tokens cannot qualify.

Defaults: ARISHA_IT_EXTRACTION_ENABLED=false and ARISHA_ENABLED=false. Approved-source/data lists default empty. Future configuration keys ARISHA_IT_EXTRACTION_SOURCE_TYPES=paste and ARISHA_IT_EXTRACTION_DATA_CLASSES=synthetic (or separately approved approved-it-work) are authority/configuration decisions, not set by this implementation. A client's dataClass claim is NOT a classifier proving content synthetic. Staff may have permission to view data without approval to send it to Azure Global.

POST input has exact keys: {kind:'tickets'|'jobs',source:{type:'paste',label,text,dataClass:'synthetic'|'approved-it-work'},acknowledgement:{version:'it-extraction-v1',sendToAzure:true}}. Existing approved Azure endpoint/deployment/API version and managed identity are reused only when enabled/configured. Inference transport uses a single strict-schema request with no tools, no retries, selected text only and bounded response. No actual source file, email, SharePoint download, hidden screen, chat history, staff directory or database context is sent.

Returns proposed raw fields plus exact UTF16 source offsets, canonical source SHA256, validation errors and warnings. Canonical source normalizes CRLF/CR to LF, retaining blank lines. Fields with missing required information remain blocked; unknown date/enum values are not silently repaired. Human review still must decide whether source text is trustworthy and fields are semantically correct. Exact quotes do not prove source truth or defeat every prompt injection.

No persistence or operational mutations. readyForT9Preview is deliberately false until reviewed T9 fixes and handoff are integrated. Output extractionId is not an approval token. No inferred user IDs, company IDs, roles or action rights. Staff names are unresolved raw source strings marked STAFF_MATCH_REQUIRED. Duplicate, role-specific save and replay protection belong to fixed T9 and are not falsely claimed here.

Limits: 8000 Unicode code points/32000 UTF8 bytes input, 20 model rows, 4000 output tokens, 64000-byte HTTP response, 30-second timeout, one in-flight call per actor per process. Existing application request rate limit remains relevant. Process-local concurrency is NOT a distributed rate limiter or monthly spending cap. No confidential-body/source logging is introduced. Source and preview are request/response data, not durable storage; callers must not persist/log them without retention approval.

Independent source reviews of backend and combined UI/routing found no blocker for disabled, preview-only packaging. Remaining gates: actual synthetic browser CI/UAT, distributed spend/rate policy if multiple replicas, fixed T9 handoff, synthetic end-to-end model test under separate cost approval, publish/deploy/activation approval. CSV/TSV should use repaired deterministic T9 parser rather than unnecessarily invoking AI. File/OCR/Graph-content retrieval is out of scope.

Validation: local service/adapter tests, real localhost HTTP integration with signed synthetic JWT plus mock database/model, UI state race tests and React SSR render checks. No real PostgreSQL, Azure, Microsoft Graph or model inference. Browser interaction is NOT verified locally: no usable installed Playwright/browser; The new synthetic browser harness passes its local Vite transform check; actual desktop/mobile assertions are added to existing isolated CI but have not run locally.
