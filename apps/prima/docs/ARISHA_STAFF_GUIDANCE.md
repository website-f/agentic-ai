# Arisha staff workflow guidance

This is a read-only, deterministic in-app guide, not a new LLM capability, access role, workflow executor or approval service. The existing four-leader AI tools and CEO exact-batch import authority are unchanged.

The staff IT screen can open the guide. It reads the existing IT board using a pinned bearer after confirming `/me` matches the current actor. Account/token changes before or after the read are rejected; old-user data is hidden during reload. There is no new backend endpoint or grant. The demo follows the same owner identity check.

The guide contains 19 **catalog groupings**, not 19 independently verified production modules. They map to existing permitted screens or state an unavailable/separate setup requirement. Navigation is an intersection of the actual board role and currently rendered tabs. No arbitrary URL, approval, save, email, tenant action or model call is invoked. Power BI, selected SharePoint, Outlook setup and identity readiness are not inferred from this catalog.

For jobs with exact server-permitted start/submit/check/accept/return flags, it shows up to eight due-ordered next steps, current status, missing proof where known and the existing responsible/checking route. It does not fetch email bodies, documents, secrets or unrelated records. The read timestamp is labelled as a client-observed snapshot; no record revision token or completed verification is fabricated. Users must reopen the actual record, where current permissions and stale-state guards apply.

All catalog entries explain the doer, monitor/checker, approver and overseer boundaries. Joining/leaving guidance reflects the owner's two approvals (CoS + relevant Company Head) before HR Admin applies exact role/company scope; IT Lead verifies Microsoft technical setup, with Manager-approved executive delegation. The staged identity workflow remains labelled pending reviewed implementation; this guide does not create accounts, link arbitrary object IDs or grant/revoke access.

## Local evidence and remaining gates

Actual-component synthetic tests cover next steps, missing proof, read-only expansion/collapse/refresh, pending connectors/governance and stale-owner hiding. Typecheck/build must pass on the final integrated source. Real browser/staff UAT, live AI/provider health, database migration and deployed availability are separate evidence; no accessibility or security certification is claimed.
