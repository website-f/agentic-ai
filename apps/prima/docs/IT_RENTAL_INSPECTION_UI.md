# Operational IT rates, billing and six-month inspection UI

Local implementation for the owner's 1 November instruction. It is not a deployment or a verification of actual company rates, balances, assets or Microsoft connections.

- Only server `canSetRates` permits the IT Manager rate form. Real monthly MYR amounts and first-of-month effective dates are explicit. Empty rates remain unconfigured; zero must be entered intentionally. No demo rate fallback.
- Authorized IT staff select actual eligible company-linked assets for a billing month. Preview binds a rate ID and each asset version; the server rechecks these and stores the immutable snapshot. No automatic selection of all company assets, no unlinked stock billing, no implied purchase or rental ownership from registration.
- Existing historical amounts are recorded separately with evidence and a reference. Legacy stored rows are labelled unverified, including their currency/payment provenance. No invoice is sent and no payment is executed or marked paid through this UI.
- Every asset has an initial/next six-calendar-month health inspection state. Unknown history stays unknown. Service/repair records do not reset the health inspection ledger. Unsafe/attention conditions remain warnings even when a next date exists; disposed records retain history without new-entry action.
- An inspection must link to the recorder's eligible assigned IT job. The backend records an immutable inspection packet in that job log before submission. The normal job proof/technical/Manager checking workflow applies. `linked_job_accepted` means the linked job was accepted, not a separate condition certification. The observer cannot fabricate a checker status.
- Forms capture their opening version/snapshot. Background changes block save and require explicit discard/reload/review. Account changes hide old board data immediately and pin each request to the original authenticated actor.
- An owner-scoped, separate operational marker stores only request UUID and kind before sending. Web Locks prevent competing local tabs. Unknown results require exact receipt recovery or explicit server-serialized abandonment; generic errors and found:false never clear the identity. There is no sensitive payload or token persistence, automatic retry with a new UUID, or offline write queue.

## Evidence
Synthetic state/decoder/money/component tests cover roles, decimal boundaries, unknown states, selected asset/rate hashes, manual evidence, legacy bills, identity switching, cancellation and stale drafts. Actual-core integration tests exercise seeded legacy decoding, Manager rates/staff bill recovery, and month-end inspection linkage. Shared manual recovery tests remain in CI. Browser interaction, restricted PostgreSQL concurrency/RLS, real staff UAT and live deployment are separate gates. The new backend schema must be reviewed and migrated before runtime readiness; frontend flags are not proof that migration occurred.
