# Controlled cleanup SQL reconstruction — NOT deployed

Install order in a separately approved migration: reviewed base `001_init.sql`, actual procurement module, actual rental-correction module, then `db/modules/it-cleanup-v1.sql`. Cleanup is a separate transactional module; the base schema hash alone does NOT prove it is installed. No live migration or data archive was performed.

Three operational tables contain documentary nominations, recoverable same-ID archive markers, and owner-only terminal receipts. A fourth private table holds admission proofs for newly created group-plan jobs; the runtime role cannot read/write it. Missing or partial module/catalog protection fails closed. Existing baseline readiness verifiers validate the complete optional cleanup module before tolerating its exact additional triggers; the cleanup catalog verifier never calls them recursively.

Only current scoped IT staff nominate known manual records with known creators and documentary evidence. Unknown/real/mixed records remain held. A current IT Lead distinct from both nominator and creator must approve. No Manager fallback, new identity permission or role grant is created. Archive preserves the original root, ID, snapshot, all audits/receipts and identifiers. No hard deletion exists. Restoring requires exact current marker/source and dependency checks. A restored root that is subsequently corrected cannot be re-archived by replacing its original snapshot: it remains held for explicit reconciliation.

Complete owner visibility is checked across the actual installed dependency tables, including forced-RLS owner policy/inheritance. Absence is not evidence of no dependency. Historical financial/inspection/access references remain protected; ambiguous ID/tag text is conservatively held. Legacy group jobs lack proven inventory membership and hold their company assets. New group jobs use a server-derived immutable protective inventory superset of all current live nonarchived owner assets, exact IDs and canonical hashes; this is NOT proof each asset is due or completed. Only SQL-admitted jobs acquire private binding evidence. Pre-installation shape-valid metadata is not trusted. Job planKey/refs cannot be rewritten.

All mutation/dependency guards share `it-manual:create`. Current actor rights are stabilized with row locks. Exact typed payloads, canonical operation/input hashes, immutable history and owner UUID tombstones prevent forged terminal recovery. Deferred constraints require a corresponding event, receipt and archive marker before commit. Active owners may reconcile/abandon only their own UUID after loss of IT role; this does not permit a domain action.

Validation: TypeScript compilation and catalog/source mocks passed locally. Seventeen restricted-role PostgreSQL tests are authored and compiled, but NOT run locally because no disposable PostgreSQL server is available. They must pass in CI, together with actual service lifecycle/storage rollback/race tests, before release. Catalog mocks are not SQL syntax or runtime evidence. Migration rehearsal, backup/restore evidence and explicit rollout approval remain separate gates.
