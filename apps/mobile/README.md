# Agentic Office phone app (Android and iOS)

One app holds the Agentic Office and Prima. It is built with Capacitor from the same web code as the
website. The screens are stored in the app, so they open at once. Only data goes to the server,
`https://agent.oriondesk.space`.

Signing in works the same as on the website. A "Prima only" member lands in Prima with their chosen
modules. A member with both lands in the office, with its Prima entries.

## What is where

| Path | What it is |
| --- | --- |
| `app.json` | The app id (`space.oriondesk.agentic`), the name ("Agentic Office") and the server. Change them here only, then run `npm run sync`. |
| `scripts/build-web.mjs` | Builds the office (`apps/web`) and Prima (`apps/prima/apps/web`, office mode, base `/prima/`) into `www/`, laid out the way the server serves them: the office at `/`, Prima at `/prima/`. |
| `src/bridge.ts` | A small script that runs first on every page in the app (never on the website). It sends `/api/...` calls to the server with the app's sign-in, and loads big optional files from the server. |
| `scripts/identity.mjs` | Writes the id and name from `app.json` into the Android and iOS projects. |
| `scripts/gradle.mjs` | Runs the Android build with JDK 21 and the Android SDK. |
| `android/`, `ios/` | The native projects (generated by Capacitor, then committed). |

Not inside the app, to keep it small (about 10 MB): the guide's videos and screenshots, Prima's
receipt reader (`/prima/ocr/`, about 11 MB) and Prima's face models (`/prima/face-models/`, about
6.5 MB). The app downloads them from the server the first time someone needs them. The server lets
only the app read the receipt reader and face models from another origin (see
`deploy/nginx/web.conf`).

## How the app signs in

The website signs in with cookies. The app cannot rely on cookies: its pages run at
`https://localhost` (Android) or `capacitor://localhost` (iOS), not on the server, and iPhones block
cookies from another site. So:

1. Every call from the app says `X-Agentic-Client: app`.
2. When someone signs in (password, emailed sign-in password, or the two-step code), the server
   answers with the session token in the `X-Agentic-Session` header instead of cookies.
3. The app keeps the token in the phone's secure storage (iOS Keychain, Android Keystore) and sends it
   on every call as `Authorization: Bearer <token>`. Live updates (`/api/events`) use it too.
4. Signing out ends that session on the server, and the app forgets the token. A password change
   signs out every other device and keeps this one.

It is the same server-side session as a browser's, with the same expiry. Browsers still use cookies
and the CSRF check. The server accepts calls from another origin only from the two app origins, and
never with cookies (`AGENTIC_APP_ORIGINS`, default `capacitor://localhost,https://localhost`).

The server needs this change deployed before the app can sign in (P104 API: `apps/api/agentic/api/deps.py`, `main.py`).

## Build for Android on Windows

You need these once:

* Node.js 22 or newer.
* JDK 21. Gradle 8.14 does not run on JDK 25. The build looks for one under
  `%LOCALAPPDATA%\Programs\Microsoft\jdk-21*` or `C:\Program Files\Microsoft\jdk-21*`. You can also
  set `JAVA_HOME` to a JDK 21.
* The Android SDK in `%LOCALAPPDATA%\Android\Sdk`, with `platforms;android-36` and
  `build-tools;36.0.0`. Android Studio installs them, or use the SDK's `sdkmanager`.
* The office and Prima packages installed: `pnpm install` at the repo root, and `npm ci` in
  `apps/prima`.

Then, in `apps/mobile`:

```
npm ci
npm run android:debug
```

This builds the web, copies it into the Android project and builds
`android/app/build/outputs/apk/debug/app-debug.apk`. To install it on a phone with USB debugging on:
`adb install -r android/app/build/outputs/apk/debug/app-debug.apk`.

For a store build: open `android/` in Android Studio, then Build > Generate Signed App Bundle. It
makes the upload key the first time. Keep the key file and its password out of the repo, in a
password manager: every later update must be signed with the same key.

To test against a server on this PC instead of the live one (never for a release):
`set MOBILE_SERVER=http://localhost:8519` before `npm run android:debug`, then
`adb reverse tcp:8519 tcp:8519`.

## Build for iOS (on a cloud Mac)

An iPhone app can only be built on a Mac. You do not need to own one: Codemagic or GitHub Actions
lend one per build. You need:

1. **An Apple Developer account** (USD 99 a year) at developer.apple.com, in the company's name.
2. **The app id**: in the Apple Developer site, Certificates, IDs & Profiles > Identifiers > add an
   App ID with the same id as `app.json` (`space.oriondesk.agentic`, or the final one).
3. **The app in App Store Connect** (appstoreconnect.apple.com > My Apps > +): name, that bundle
   id, a SKU (any text).
4. **An App Store Connect API key**: App Store Connect > Users and Access > Integrations > App Store
   Connect API > generate a key with the "App Manager" role. Download the `.p8` file (you can download
   it only once). Note the Key ID and the Issuer ID. These let the cloud Mac sign the app and upload
   it without your password.

### With Codemagic (simplest)

1. Sign up at codemagic.io with the GitHub account that has the repo, and add the repo.
2. Team settings > Integrations > Developer Portal: add the API key (Issuer ID, Key ID, the `.p8`).
3. Add `codemagic.yaml` at the repo root, along these lines:

```yaml
workflows:
  ios-testflight:
    name: iOS TestFlight
    instance_type: mac_mini_m2
    integrations:
      app_store_connect: <the name you gave the key in step 2>
    environment:
      node: 22
      xcode: latest
      ios_signing:
        distribution_type: app_store
        bundle_identifier: space.oriondesk.agentic
    scripts:
      - name: Install
        script: |
          corepack enable && pnpm install --frozen-lockfile --filter web...
          (cd apps/prima && npm ci -w @prima/core -w @prima/web)
          (cd apps/mobile && npm ci)
      - name: Build the web and sync iOS
        script: cd apps/mobile && npm run build:web && npm run identity && npx cap sync ios
      - name: Signing
        script: xcode-project use-profiles
      - name: Build number
        script: cd apps/mobile/ios/App && agvtool new-version -all $BUILD_NUMBER
      - name: Build
        script: xcode-project build-ipa --project apps/mobile/ios/App/App.xcodeproj --scheme App
    artifacts:
      - build/ios/ipa/*.ipa
    publishing:
      app_store_connect:
        auth: integration
        submit_to_testflight: true
```

4. Start the workflow. When it finishes, the build appears in App Store Connect > TestFlight after
   Apple's check (about 10-30 minutes). Add testers there (their Apple ID emails); they install
   "TestFlight" from the App Store and then the app.

### With GitHub Actions

Use a `macos-latest` runner with the same steps: install, `npm run build:web`, `npm run identity`,
`npx cap sync ios`, then build and upload with `fastlane` (`match` or the API key for signing,
`pilot` for TestFlight). Store the `.p8` content, Key ID and Issuer ID as repository secrets, never in
the repo. Codemagic does the signing for you; GitHub Actions needs more setup.

## Checks

* `npm run typecheck`: the bridge.
* The API's tests for the app sign-in: `apps/api/tests/test_p104_app_sessions.py`.

## Not in this first version (phase 2)

* Push notifications (Firebase for Android, APNs for iOS).
* "Sign in with Microsoft" inside the app (needs a link back into the app); the button is hidden in
  the app for now. Password, emailed sign-in password and two-step codes work.
* Fingerprint or face unlock.
* App store listings, icons and screenshots for the stores.
* Working offline beyond what the website already does.
